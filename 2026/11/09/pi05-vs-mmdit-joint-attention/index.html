π0.5 与 MM-DiT：都是 joint attention，差别在谁看得见谁

发表于2026-11-09|更新于2026-11-09|AIDeep Learning

π0.5 和 SD3 的 MM-DiT 常被一句话打发掉：「都是 joint attention」。这句话不错，但它把两件不同的事混成了一件。

joint attention 描述的是算子形状：几套 QKV 权重、一个共享的 KV 池、一次 softmax。它不描述权限：哪些 token 的 key 能被哪些 query 读到。前者两边几乎逐行相同，后者是两张完全不同的矩阵——一张是 3 段块间单向的有向图，一张是 2 段全连通的对称图。

下面把两边都摊到代码与论文附录这一级对齐：π0.5 用 openpi 的 pi0.py、gemma.py 和论文附录 A–E，MM-DiT 用 SD3 第 4 节以及它派生出来的 MoT 家族。看完应该能回答一个具体问题：为什么 π0.5 的注意力必须有方向，而 MM-DiT 不需要。

head 几何必须完全一致，这是能把 KV 拼进同一张表的前提，不是顺手做的检查。π0.5 的两个专家一个 2048 宽、一个 1024 宽，但都是 8 个 query 头、1 个 KV 头、head_dim 256——宽度不同不妨碍联合，头形状不同就联合不了。

于是「联合」的成本结构是：权重按流分开、归一化按流分开、只有 softmax 的分母是共享的。SD3 论文把这个说得很清楚，MM-DiT 的两套权重「等价于两个独立的 transformer，只把两条序列拼起来做注意力」。

剩下的全部自由度都在 mask 里。

π0.5 的 mask：三段、两处看不到

先看序列怎么排。openpi 的 tokenizer.py 里，π0.5 的输入被拼成这样一个字符串：

机器人状态被离散成 256 个分箱、写成 32 个整数塞进前缀。这一点和 π0 不同：π0 的 state 是一个连续投影出来的 token，挂在动作流最前面、自己起一个注意力块。π0.5 把它挪进前缀，因为它是观察，不是待生成的东西——pi0_config.py 的注释就写着这两条差异（state 进离散语言 token、时间步改用 adaRMS）。

前缀之后并排放着两套动作表示：FAST token（离散、自回归）和 50×32 的动作 chunk（连续、flow matching）。同一份数据训两次，两种表示各自拿一份监督。

论文附录对 mask 的描述（译）：图像 patch、提示词、本体状态用完整的前缀 mask（即双向）；FAST 动作 token 看这个前缀，并在自己块内逐 token 自回归；动作专家的 token 看前缀、也互相看，但不看 FAST token，以免两种动作表示之间泄漏信息；VLM 一侧不看动作专家，信息单向从 VLM 流向动作专家。

翻成一张权限表：

query ← key 权限 原因
前缀 ← 前缀 双向 图像 patch 与指令之间没有先后
FAST ← 前缀 可见 它是条件
FAST ← FAST 逐 token 因果 自回归监督，不能偷看后一位
专家 ← 前缀 可见 它是条件
专家 ← 专家 双向 50 个动作 token 并行去噪，同时成形
前缀 ← FAST / 专家 禁止 前缀是干净条件，不能读带噪目标
专家 ← FAST 禁止 两种动作表示隔离

所以「π0.5 是 causal 的」这句要收窄一点：因果只发生在块边界和 FAST 块内部。50 步动作 chunk 内部是全双向的，和 MM-DiT 的图像 patch 一模一样——flow matching 本来就要整块一起成形。让它算「causal」的不是逐 token 的阶梯，而是序列被切成有先后关系的块，且跨块的边单向。

在 openpi 里这一点比论文更直白。embed_prefix 给每个图像和文本 token 追加 ar_mask += [False]（全在同一块）；embed_suffix 才追加 [True] + [False] * (H - 1)（状态/动作另起一块）。而 make_attn_mask 只用了一行：

$$M_{ij} = \mathbb{1}\left[\mathrm{cumsum}(m_a)_j \le \mathrm{cumsum}(m_a)_i\right]$$

块号不大于我的位置全部放行。这是 prefix-LM 的写法，不是 LLM 的 tril。「一块」可以是 1 个 token（FAST 块，逐 token），也可以是 50 个 token（动作 chunk，整块互通）——同一个函数，两种粒度。

顺带一个容易看漏的地方：π0.5 把时间步的注入方式也换了。π0 把 τ 和带噪动作拼起来过一个 MLP；π0.5 单独算 swish(W2 · swish(W1 · φ(τ)))，再用 adaRMS 打进动作专家每一层的 norm（RMSNorm 里 Dense(3d) 出 scale/shift/gate）。这套「时间步 → 逐层调制」正是 DiT 系的 adaLN modulation。在条件注入这一层，π0.5 离 MM-DiT 比离 π0 更近。

MM-DiT：双向是免费的，因为它只有一种 target

SD3 第 4 节的论证只有三句：文本和图像表征「概念上差别很大」，所以用两套权重；两套权重等价于两个独立 transformer，只把序列拼起来做注意力；这样「图像与文本之间可以双向流动信息」，换来更好的文字理解与排版。

双向之所以能白拿，是因为 MM-DiT 只有一种监督目标：去噪。图像 patch 是个集合，没有自然顺序，任意两个 patch 互看都不构成泄漏——它们本来就该同时成形。文本在这套架构里不是待生成的东西，只是条件：它进了同一条序列、有自己的权重、也能读图像（这正是「bidirectional flow」的含义），但模型从不去预测下一个文本 token。

位置编码把同一个判断又写了一遍：图像 patch 加 2D 正弦位置编码，文本侧不加。文本被当成集合，图像被当成网格。

MoE 那套「更多专家、更少激活」在这里不适用。MoT 把分流推到 attention 投影本身：按模态解耦所有非 embedding 参数（FFN、注意力矩阵、LayerNorm），注意力仍在全序列上做。参数约翻倍，每 token 激活不变——动机不是省算力，是消解模态冲突。

而一旦模型既要 AR 理解、又要扩散生成（比如 Cosmos 3 的 MoT：reasoner 塔因果、generator 塔双向），方向性就回来了，而且是非对称的：generator 的 query 能读 reasoner 的 KV，reasoner 的 query 读不到 generator。这和 π0.5 那条「VLM 不看动作专家」是同一条原则的另一种写法——干净的条件可以被子孙读，子孙不能反过来改写条件。

所以真正的谱系不是「因果 vs 双向」，而是看 target 的个数：

  • 只有一种 target（纯生成）→ 全双向，方向性没有意义；
  • 两种 target 共存（AR + 去噪、离散 + 连续）→ 必须给信息流定向，mask 从对称图变成有向图。

π0.5 在第二格，MM-DiT 在第一格，Cosmos 3 那种双塔 MoT 落在第二格的另一侧。三者的算子完全同构。

逐项对照

维度 π0.5 MM-DiT（SD3 8B / FLUX 前段）

两边的 block 数、宽度、层数都能从 config 复算：gemma_2b 是 width 2048 / mlp 16384 / depth 18，gemma_300m 是 1024 / 4096 / 18（311M 参数）；SD3 的定标式是 hidden = 64d、MLP = 4×64d，8B 档取 d=38 → 2432 / 9728。

工程账：同一条序列，两种重算范围

这是两种 mask 在部署上最直接的兑现。

π0.5 采样时先跑一次前缀、把 KV 存下来，之后 10 步 Euler 只算 50 个 query：

  • 每步注意力对数：50 × (850 + 50) ≈ 4.5×10⁴
  • 一整条控制步（含前缀自注意力 850² 一次）：约 1.2×10⁶ 对

MM-DiT 没有这个优待。4096 个图像 token 每一步都换一份新 latent，KV 必须重算；文本那 154 个 token 在采样期间不变、原理上可缓存，但只占 3.6%，改不了量级：

  • 每步注意力对数：4250² ≈ 1.8×10⁷
  • 一次采样 28 步：约 5.1×10⁸ 对

$$\frac{28 \times 4250^{2}}{850^{2} + 10 \times 50 \times 900} \approx 430$$

差 430 倍。这不是模型大小造成的，是两个结构量的差：序列长度的平方乘以步数，对固定长度前缀加 10 个短 query。π0.5 能在机器人上跑 10 步，结构上的原因是「待生成的东西只有 50 个 token」——它把昂贵的部分放在前缀，而前缀一个控制周期只算一次。

Cosmos 3 的 DROID 策略把去噪压到 4 步，是同一个约束的另一种解法：既然每步都要重算整块，那就少走几步。

代价也要说清。MM-DiT 的双向让 4096 个 patch 在一次 softmax 里互相协调，排版、几何一致性这类全局性质是「全见」买来的；给 patch 编一个光栅序、只允许看前面，等价于把二维协调压成一维链，得用层数补。反过来，把 π0.5 改成全双向会直接毁掉双目标训练——FAST token 会读到 flow 分支的答案，自回归那一半的损失立刻失去意义。

mask 不是常量：它随训练阶段和推理路径变

同一份代码，在 π0.5 的两个阶段画的是不同的图。

预训练 280k 步只有离散 token——文本、检测框、FAST 动作 token，全是 next-token prediction。这时序列里只有一种 target，动作专家的权重根本不存在（$\alpha = 0$），「专家 ⇏ FAST」这条禁令无从谈起：图里只有前缀和 FAST 两块，块间因果。

后训练 80k 步才挂上动作专家（随机初始化）和 flow matching 头，$\alpha = 10$，第二种 target 进场，前一张图才长成三段式、才需要那两条禁令。SD3 那种「全双向」则是第三种情况：从头到尾只有去噪一个 target。

部署时图还会再变一次。FAST 块不在（动作不走离散表示了），但要先自回归吐一遍子任务文本，再把这段文本并进前缀、把前缀 KV 冻结，最后动作专家 10 步出 chunk。所以真正跑在机器人上的图是两段：一段因果的文本生成，接一段双向的 chunk 去噪。

这解释了为什么「换个 mask 重训一遍」在实践中可行：mask 是训练配方的函数，不是模型的固有属性。同一条注意力算子，配几个 target 就画几张图。

三个可以带走的判断

  1. joint attention 决定算得多贵，mask 决定能学什么。 前者的形状两边几乎一样，后者才是设计空间。
  2. 方向性不是保守，是多目标共存时唯一的隔离手段。 一条序列里放两个能互相预测的表示，就必须写明禁令；只有一个 target 时，定向纯属自找麻烦。
  3. 位置轴跟着语义走。 有序过程用一条连续位置轴（动作 token 接着前缀往下编号），无序集合用 2D 位置或干脆不给（文本侧）。

反过来说，看到一个新 VLA：先问它有几个 target，再看它的 ar_mask 怎么切块，基本就能推断出它的 mask 图长什么样、KV 能缓存多少、实时性上限在哪。这比记「谁用了 joint attention」有用得多。
