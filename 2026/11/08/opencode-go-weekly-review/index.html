OpenCode Go 订阅一周用量复盘：¥71.5（$10）能跑出多少 token

发表于2026-11-08|更新于2026-11-08|综合实践

先给四个数。本机一周（2026-11-01 00:00 起，复算截至 11-08 10:58，北京时间，下同）经 magpie 网关走 OpenCode Go 通道，共发出 6,474 次请求，成功率 98.1% [D01]；输出 token 5,046,952；缓存读取 1,002,195,397，命中率 96.66% [D02]；按官方牌价折算，这批流量的等价价值约 ¥117（$16.4）。OpenCode Go 是每月 ¥71.5（$10）的开源模型订阅，额度按一组已内置计价的开源模型发放 [L01]；这一周走的全部是 OpenCode 的 Go 端点，没有直连流量混入（provider 过滤口径）。金额叙述统一按 1 美元 ≈ 7.15 元人民币换算（本文计价口径），牌价原始报价为美元的保留美元并标注。四个数和月费之间隔着命中率、峰谷时段、窗口刻度三层结构，下文用账本逐段算清。

一周用量

数据源是 magpie 的本地账本 usage.jsonl，逐请求记录模型名、状态码、端到端时长与 token 明细。本文按 provider 字段筛出 OpenCode Go 通道后以脚本复算，只读账本，未改动任何文件；dsh 是本机代理所有会话的框架入口，openclaw 与脚本只占零头。口径：token 与成本只统计 status==200 的 6,348 条请求，126 条 499 是 agent 侧主动中止、没有计费计量、也就进不了后文的账 [D01]；这 126 条占全周 1.9%，请求侧 token 未回流计量，账面因此比真实发送量略小。复算切断点取 11-08 10:58:55，即当周第 6,474 条记录落账的时刻；到当天下午复算截止时，账本又追加了 305 条请求且全部成功 [D18]，所以本文算的是截在周内低点上的一周，账面偏保守。

形态比想象中集中：11-03（周二）单日 1,501 次请求、输出 1,335,758 token，差不多是前两日合计的五倍；周二至周四三天合计 4,371 次请求，占到全周的 68%（4,371/6,474，本文推算）。输出量的峰在 11-03（1,335,758），请求量的峰在 11-04（1,591），两个峰错开一天，批次与短交互交替。低谷出现在周初，11-01 加 11-02 两天只有 410 次；周五起回落，但日均仍维持在 550 次上下，周日至切断点的 631 次说明周末也没有停。调用方九成六是 dsh（6,231 次），其余是 openclaw（162 次）和脚本直连（81 次：httpx 73、urllib 7、curl 1）[D17]，负载基本全部来自 agent 工作流。逐日折算的等价账同样跟着负载走：周二 ¥28.0、周三 ¥26.0 为当周峰值两天（逐日分账见 [D20]），全周合计约 ¥117（本文推算）[D20][D11][D12]。

token 构成方面，200 口径下输入 34,604,281，缓存读取 1,002,195,397，输出 5,046,952，其中 reasoning 2,542,093，约占输出的一半 [D02]；这项计在输出流里、单独可查，对账时能分清成本走向。命中率 96.66%（按缓存读取对输入总量之比记）换个读法：每约 29 个缓存读取 token 才对应一个未命中的新输入，重复前缀直接从缓存读走，真正按输入单价重新计费的只有零星新增 [D02]；输入总量只是缓存读取的约 3.5%，配额的大头实际由命中部分决定。两模型的命中结构也不同：DeepSeek 部分 97.5%、GLM 87.6%（本文推算），后者多承担前缀更杂的会话。按 bigmodel 给出的 GLM 系列 Token 与汉字约 1:1.6 的换算比，全周 5.0M 输出 token 约合 800 万汉字的成文量（本文推算）[L03]。

想复现这篇的账，核心三步：按 provider 筛出通道（本文全部落在 OpenCode 的 Go 端点）、把每条请求的时间戳转成 UTC 判峰谷、对 in、cache_read、out 各乘当档牌价累加 [D19]。全部计算在本机离线完成：脚本是只读的，算完即走，账本从始至终未被改动。

模型分布与延迟

一周的 200 流量几乎全部压在两个模型上：6,348 条成功请求里，DeepSeek 占 5,645 条、GLM 占 700 条，之外的散点请求只有 3 条。端到端时长按毫秒字段取最近邻秩百分位，统计口径是整周成功请求：

deepseek-v4.1-flash 5,645 23,593,617 924,542,464 4,412,191 8,520 / 44,097 / 177,410 ≈4.5 s / ≈26 s
glm-5.3-flash 700 11,010,504 77,652,736 634,741 9,899 / 35,689 / 166,478 4,065 / 14,027 ms

[D05][D06][D07][D08][D09]

DeepSeek 的 TTFT 两轮复算差小于 300 ms，表内取秒级四舍五入，GLM 列沿用完整毫秒值；TTFT 只对带该字段的请求计入。p50 意味着一半请求在 8.5 秒上下收尾，p90 把长尾与常态拉开约五倍，p99 已到三分钟量级、多计入批量任务的队列尾部。

结构上 DeepSeek 占了 89% 的请求（5,645/6,348），两模型合计覆盖 6,345 条 200 请求，余下 3 条散点本文不必逐单展开 [D05][D08]；平均每次输出约 782 token、聚合吞吐约 39 tok/s——吞吐按输出汇总除以全部请求时长之和计，摊平了并发与排队，当整周平均产能读 [D07]；GLM 首字更快（p50 约 4.1 s）、单次输出约 907 token（本文推算），只承担部分会话与兜底。对并发 agent 而言，首字时延比全程更影响会话开工节奏——后续 token 已在流式回传，等首字与等全文是两种等待模型；两家的 p50 都压在 4 秒半上下。p99 接近三分钟的记录集中在长思考的批量任务上，不代表交互体感，正文不作进一步引申。GLM 段输出的 634,741 token 按官方 1∶1.6 换算约合 102 万汉字 [L03]。

配额窗口

OpenCode Go 把每个模型的月额度切成三层窗口：5 小时窗按月额度的 20% 计，7 天窗 50%，月窗 100% [L01]。两个主力模型的月额度并不均等：DeepSeek V4.1 Flash 给 $100（约 ¥715），GLM-5.3-Flash 给 $60（约 ¥429），多数旗舰与小模型在 $15–30 一档（约 ¥107–214）[L01]——额度档位直接决定谁扛得住主力，¥107 一档只够轻量轮换。窗口读数来自 quota-history 的周期快照，按剩余百分比记，与请求数口径无关；同一百分比下，不同模型的绝对额度可以差出一个量级 [L01]。月窗本轮自 10-30 起算。

2026-11-08 10:56 读到的三个窗口：

窗口 读数
5 小时（滚动） 剩 100%（本窗未动用）
7 天窗（11-02 00:00 → 11-09 00:00 UTC） 已用 36%
月窗（10-30 → 11-29 14:02 UTC） 已用 24%

[D16]

半小时后键内的末次读点已推进到 7 天窗 39%、月窗 26% [D16]，38 分钟内在 7 天窗刻度上走了 3 个百分点，扣减随用量实时走，两组快照源在同一读点上互相对齐 [D16]。5 小时窗是滚动短窗，读数停在满格只说明本窗起点之后尚未起扣，单人单机的持续写入从没把短窗打满。以月窗 24% 对应约 9 天线性外推，全月约 ¥572 官方等价，相对 ¥71.5 月费约 8 倍杠杆（本文推算，只按「照此节奏」的假设读，牌价固定在 11-08 快照）。结构上最先到线的是 7 天窗：深度只有月窗一半，周中批量高峰先在这里报警；月窗触顶时的官方口径是仍可继续用免费模型 [L01]。顺带一对照：本周等价 ¥117 已经超过一个月费，月窗刻度上却只走到 24% [D16]。

若走官方 API

等价价值的算法不复杂：把每条 200 请求的输入、缓存读取、输出，分别乘以该请求所在时段的牌价再求和 [D19]。等价价值同时就是 Go 配额的扣减口径——Go 按官方牌价把用量折成美元记进窗口 [L01]，所以 ¥117 既表示「值多少」，也表示「烧掉多少配额」。判定方法是把每条请求的时间戳转成 UTC，再按周几与时点分桶 [D10]。以 DeepSeek 谷段为例，全周流量代入官方牌价就是 15.75M 输入 ×$0.15、603.68M 缓存命中 ×$0.003、2.77M 输出 ×$0.60，合计约 ¥41.7（$5.83）[D11]。按官方页，deepseek-flash 就是本文通道里的 deepseek-v4.1-flash（旧名仍被接受），1M 上下文、单次输出上限 384K [L02]。峰段按官方定义为 UTC 01:00–04:00 与 06:00–10:00（周一至周五，节假日除外）[L02]，本周不含中国公众假期，判定口径成立；官方页另注并发上限 2,500 条 [L02]；GLM 部分按 Go 计价牌价代入。三条通道吃的是同一批 token，通道差只在牌价，token 构成不随通道变化；一批任务横跨峰谷时，各请求按各自时刻的单价分别计。并排如下：

通道 牌价（每 1M token，输入/缓存/输出） 同流量账单
DeepSeek 官方 API 谷 $0.15 / $0.003 / $0.60；峰 $0.30 / $0.006 / $1.20 [L02] ≈¥86.4：峰 ¥44.7（2,033 次）、谷 ¥41.7（3,612 次）[D10][D11]
bigmodel 直连 GLM-5.3-Flash ¥0.8 / ¥0.23 / ¥2.8 [L03] GLM 部分 ¥28.45（直连人民币原价，本文推算）[D13]
Claude Sonnet 类闭源 API $3 / $0.30 / $15 ≈¥3,433（$480.18）[D14]
OpenCode Go DeepSeek 牌价与官方逐项相同；GLM $0.15 / $0.03 / $0.50 [L01] 本周等价消耗 ≈¥117 ≈ ¥86.4 + ¥30.7（$16.4 = $12.09 + $4.30）[D11][D12]

这张表可以一句话读出：同一份流量走 Go 与走官方 DeepSeek 完全重合，差距全部出现在 GLM 与闭源两条侧线上。Sonnet 行仅作对照价位刻度使用，并非在用通道。四条一句话级结论：

  • DeepSeek 部分直连官方 API 与 Go 计价逐项相同 [D15][L02]，Go 的折扣全部来自「¥71.5 月费包 ¥715 月额度」（官方原始表述为 $10 包 $100）的结构 [L01]，不在 token 单价上；DeepSeek 部分等价 ¥86.4（$12.09）已经是月额度的 12% [D11]。
  • GLM 是反例：Go 计价 ≈¥30.7（$4.30）——¥30.7 对 ¥28.45，贵约 8%（本文推算），输入/输出单项牌价贵约三成、缓存项相对便宜对冲一部分后总量仍贵，直连账 ¥28.45 由 11.01M 输入 ×¥0.8、77.65M 缓存命中 ×¥0.23、0.63M 输出 ×¥2.8 三笔组成 [D13]，纯 GLM 用量直连更划算；智谱自己也把 token 订阅搬上了天猫店，个人版每月 118 元起 [L05]，两条路都在收拢个人用户，而 Go 的价值在跨模型打包 [L01][D12][D13]。
  • 同流量按 Sonnet 类牌价折到 ≈¥3,433（$480.18），账面主要压在缓存读取上，其构成是 34.60M 输入 ×$3、1,002.20M 缓存读取 ×$0.30、5.05M 输出 ×$15 [D14]；这不是质量对比，只是提示 agent 负载下缓存单价对账单的权重远高于输出单价。
  • 峰谷仍有余量：峰段 2,033 次请求带着 7.84M 输入、320.86M 缓存、1.64M 输出折 ¥44.7（$6.25），请求量只占 36%（DeepSeek 请求内）、账面却过半，是峰段牌价整体翻倍的结果 [D11]；若 DeepSeek 流量全部落在谷时段，其段账从 ¥86.4 降到约 ¥64.1，省约 26%；按全家通等价账 ¥117 计约省 19%（本文推算）[D10][D11]。

bigmodel 另有积分制的 GLM Coding Plan：Lite 档每周 10,000 积分（5 小时窗 2,000），GLM-5.3-Flash 按 2.3/0.56/8 的系数折积分，非高峰再对折，95% 命中口径下周额度折算约 1.46–2.92 亿 tokens [L04]；以该公式计，本周 GLM 流量全高峰口径约 7,400 积分、非高峰对折约 3,700，占一份 Lite 周额度（10,000 分）的 37%–74%（本文推算）[L04]，单独为此订阅一份显得多余。另注意官方页提示用量限制可能随早期反馈调整 [L01]，本文全部读数固定在 11-08 的账本快照上。

对「主力 DeepSeek Flash、前缀缓存稳定」的 agent 工作流，Go 目前是最干净的性价比通道——杠杆成立的前提正是主力落在月额度最大的那一档 [L01]：DeepSeek 单价与官方一致，折扣来自额度结构而非缓存差价，同一份月费里换模型几乎零成本 [L01]。这个判断只在单周窗口内给出。

局限

三点说在前面：样本是一台机器一个人的 7.4 天窗口，结论只对本机这类 agent 负载成立，不做群体外推；月度外推依赖「负载节奏不变」的线性假设，只值「照此节奏」的读法；官方牌价取自 2026-11-08 的会话内页面快照，零外网授权下未做在线复核，页面如有更新以官方页为准。
